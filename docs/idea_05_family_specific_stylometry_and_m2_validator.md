## 1. 背景と解決すべき課題（なぜ試す価値があるか）

本ネタは、**① ファミリー内リランキング（`sibling_style.py`）の特徴量最適化** と **② オフライン OOF と Public LB の乖離を埋める検証プロトコル** の 2 つを組み合わせた実践的改善案です。

### 課題 ①：一律のスタイロメトリー特徴量ではファミリーごとに得意・不得意が分かれる
現行の `sibling_style.py`（Roman Tamrazov V40A：148次元）と、新規公開された `victorzhong0110` の長さ正規化フィンガープリント（`per100w` 指標を中心とする 81次元）、および両者の結合（229次元）を当チームの `train.csv`（2,699行）上で 5-Fold Grouped CV 比較した実測結果は以下の通りです：

| 識別対象ペア | 148次元 (現行 V40A) | 81次元 (Victor `per100w`) | 229次元 (Hybrid結合) | 最適特徴量セット |
| :--- | :---: | :---: | :---: | :--- |
| **Gemini 3.7 vs 3.8** | **`0.6533`** | `0.5600` | `0.6233` | **148次元 (V40A)** |
| **GPT-5.6 sol vs terra** | `0.5300` | **`0.5733` (+4.3%)** | `0.5500` | **81次元 (Victor)** |
| **GLM-5.3 vs Flash** | `0.5267` | **`0.5400` (+1.3%)** | `0.5367` | **81次元 (Victor)** |
| **Claude 4.6 vs 4.8** | `0.7133` | `0.7033` | **`0.7200` (+0.7%)** | **229次元 (Hybrid)** |
| **Claude Fable5 vs Sonnet5** | **`0.7158`** | `0.6656` | `0.7124` | **148次元 (V40A)** |

* **発見された事実**:
  GPT-5.6 兄弟（`sol` vs `terra`）や GLM 兄弟においては、文章長（40〜250 words）の交絡を `per100w` で厳密に正規化した 81 次元特徴量の方が **+1.3%〜+4.3% 高い識別能** を発揮します。一方、Gemini 兄弟では 148 次元特徴量が優位であり、Claude Opus 4.6 vs 4.8 では 229 次元結合が最高精度（72.0%）を記録しました。

### 課題 ②：18回答完備の通常 OOF（$m=18$）はプロンプト依存モジュールの評価で LB と逆相関する
Discussion [Topic 753177] にて、15 回の実機提出とオフライン OOF の相関（Pearson / Spearman）を測定した極めて重要なデータが共有されました：
* **全回答 OOF（$m=18$）**: 相関係数 **`0.13 / -0.17`（ほぼ無相関〜逆相関）**
* **疎抽出 OOF（$m=2$：各プロンプトから2回答のみ抽出）**: 相関係数 **`0.79 / 0.58`（初期10提出では `0.91 / 0.82`）**

## 2. 提案手法の数理・技術仕様

### (1) Family-Specific Stylometry Routing（ファミリー別特徴量ルーティング）
`sibling_style.py` の `apply_grouped_style_residual` 関数を拡張し、ファミリーごとに使用する特徴量行列 $X_{\text{family}}$ を切り替えます：
* `claude` $\to$ $X_{229}$（148次元 + 81次元結合）
* `gemini` $\to$ $X_{148}$（現行 V40A）
* `gpt` & `glm` $\to$ $X_{81}$（Victor 長さ正規化 81次元）

これにより、各ファミリーの内部 OOF 精度（`bacc`）が底上げされ、信頼度係数 $\text{reliability} = \text{clip}\left(\frac{\text{bacc} - \text{chance}}{0.15}, 0, 1\right)$ が自然に向上します。

### (2) $m=2, 3$ 疎抽出 OOF 検証と LB ギャップ標準偏差 $\text{SD}_{\text{gap}}$ の事前計算
2 つの候補モデル $A, B$ を比較する際、以下の 2 指標をローカルで必ず算出してから提出可否を判断します：

1. **$m=2$ モンテカルロ OOF**:
   各 Validation Fold のプロンプトからランダムに $m \in \{2, 3\}$ 行のみを 15 回リサンプリングし、テスト時と同一の階層クラスタリング＋Sinkhorn を通した平均 Balanced Accuracy を計測する。
2. **ペア差分分散（Public LB 1,200行上の揺らぎ幅）**:
   モデル $A$ と $B$ の OOF 予測において「片方だけが正解している行の割合（Disagreement Rate）」を $f$ としたとき、Public LB（約 1,200 行）におけるスコア差の標準偏差は次式で近似されます：

\[
\text{SD}_{\text{gap}} \approx \sqrt{\frac{f}{1200}}
\]

* $f = 1\%$（微調整）のとき：$\text{SD}_{\text{gap}} \approx 0.003$
* $f = 10\%$（別モデル変更）のとき：$\text{SD}_{\text{gap}} \approx 0.009$

## 3. 期待されるメリット

* **GPU 時間ゼロ（純粋 CPU 処理・数秒）での精度底上げ**:
  `ntl_style.py` は正規表現と NumPy のみで動作し、4,000 行の抽出にかかる時間はわずか 2〜3 秒です。9 時間タイムアウトのリスクを一切増やさずに GPT / GLM / Claude の兄弟境界を補強できます。
* **無駄な提出スロット消費の防止**:
  $m=2$ OOF と $\text{SD}_{\text{gap}}$ により、プロンプト平均差し引き（Centered Twin）や Sinkhorn の過剰適合をローカル段階で確実に棄却できます。

## 4. 導入に伴うリスク・デメリット・制約事項

> [!IMPORTANT]
> **高次元化（229次元）による少数サンプルでの過学習リスク**

1. **ファミリー内サンプル数の制約**:
   * 公式 `train.csv` 内の 1 ファミリーあたりの行数は、GLM（2モデル）で 300 行、Gemini（4モデル）で 600 行、Claude / GPT（5モデル）で 750 行です。
   * 300 行しかない GLM に対して 229 次元の特徴量を投入すると次元数がサンプル数に近づき過学習するため（実際に上の表でも GLM は 81次元単体の方が 0.5400 と高く、229次元では 0.5367 に微減）、**GLM と GPT には 81 次元単体（または L1/L2 強正則化）のみを適用する規律** が不可欠です。
2. **外部重み（`ntl_style_model_weights.csv`）の直接使用は厳禁**:
   * データセットに同梱されている事前学習済み重みはサードパーティ生成データ上で fit されており、公式 Train とは表記レジスタが異なるため単体精度が 0.26 と低いです。必ず推論パイプライン内で公式 `train.csv` に対して `GroupKFold` で再 fit する方式（`sibling_style.py` の枠組み）を使用する必要があります。
